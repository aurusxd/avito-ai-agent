# Avito AI Agent

ИИ-бот для Авито: парсит объявления по заданным категориям во всех регионах РФ, отбирает продавцов с 3+ объявлениями, ведёт с ними трёхэтапную переписку через реальный браузер с имитацией человеческого поведения, распознаёт заинтересованных через ИИ-анализ ответов и мгновенно отдаёт лиды оператору в Telegram с историей переписки. Управление — через веб-панель: статистика, скрипты, задержки, категории, расписание, старт и пауза.

Настройки в панели применяются на лету, без перезапуска бота.

## Как это работает

```
                 ┌─────────────────────────────────────────────────────────┐
                 │                     Веб-панель (SvelteKit)              │
                 │  Дашборд · Категории · Парсер · Скрипты · Расписание ·  │
                 │                 Аккаунты (+ вход через noVNC)           │
                 └───────────────────────────┬─────────────────────────────┘
                                             │  HTTP, X-Panel-Token
                 ┌───────────────────────────▼─────────────────────────────┐
                 │                    FastAPI backend                      │
                 │                                                         │
                 │  parser ──► sellers/listings                            │
                 │  outreach ──► ротация, лимиты, расписание ──► Playwright│
                 │  ai_pipeline ──► вариации + анализ ответов ──► DeepSeek │
                 │  leads ──► детект интереса ──► Telegram                 │
                 │  APScheduler: доставка лидов, суточные сбросы           │
                 └──────┬──────────────┬──────────────┬───────────────────┘
                        │              │              │
                 ┌──────▼─────┐ ┌──────▼──────┐ ┌─────▼──────┐
                 │  Авито     │ │ DeepSeek /  │ │  Telegram  │
                 │ (браузер + │ │  OpenAI     │ │ (aiogram)  │
                 │  прокси)   │ │             │ │            │
                 └────────────┘ └─────────────┘ └────────────┘
```

Каждая внешняя интеграция скрыта за `Protocol`-интерфейсом и имеет фейковую реализацию, поэтому весь бэкенд работает и тестируется без реальных ключей, аккаунтов и трафика. Переключение на боевые клиенты — одним флагом в `.env`.

Конвейер по продавцу:

1. **Парсер** обходит категорию, отбирает продавцов с 3+ объявлениями, пишет `sellers` и `listings`.
2. **Outreach** выбирает аккаунт из ротации (с учётом суточного лимита, задержки и окна расписания), берёт шаблон нужного этапа, прогоняет его через ИИ для уникализации и отправляет через реальный браузер. Каждый этап отправляется ровно один раз (уникальный ключ `message_log(seller_id, stage)`).
3. **ai_pipeline** читает входящие ответы и классифицирует их как `interested | neutral | negative`, обновляя статус продавца.
4. **leads** ловит заинтересованных и отдаёт лид оператору в Telegram с историей переписки. SLA — меньше 2 минут.

## Стек

- **Браузерная автоматизация** — Playwright (Python), headed Chromium под Xvfb.
- **ИИ** — DeepSeek API (основной), OpenAI (запасной), за общим интерфейсом `AIClient` с авто-фолбэком.
- **Telegram** — aiogram.
- **Панель** — SvelteKit + TailwindCSS + shadcn-svelte.
- **API** — FastAPI, SQLAlchemy 2 (async), Pydantic v2, SQLite, Alembic.
- **Планировщик** — APScheduler, встроен в lifespan FastAPI.
- **Прокси** — интеграция с кабинетом провайдера (sticky-сессии по API).
- **Инструменты** — uv, ruff, pytest (+ hypothesis), pyright, loguru, Docker Compose.

## Быстрый старт

Нужен только Docker с Docker Compose. Всё остальное собирается в образах.

```bash
git clone <repo-url> avito-ai-agent
cd avito-ai-agent
cp .env.example .env
docker compose up -d --build
```

Панель — http://localhost:3000, токен по умолчанию `dev-panel-token` (поле `PANEL_API_TOKEN` в `.env`).

Наполнить БД тестовыми категориями, шаблонами сообщений и демо-аккаунтом:

```bash
docker compose exec backend python -m app.db.seed
```

Со свежим `.env` всё поднимется на фейковых клиентах: панель, парсер, отправка и ИИ работают на сид-данных, никаких внешних ключей не требуется. Порядок перевода на боевой режим — ниже.

Проверить, что всё живо:

```bash
curl http://localhost:8080/health
```

Порты меняются переменными `BACKEND_PORT` (по умолчанию 8080), `PANEL_PORT` (3000) и `VNC_PORT` (6080).

## Конфигурация (`.env`)

Полный список ключей — в [`.env.example`](.env.example). Самое важное сгруппировано ниже.

### Доступ к панели

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `PANEL_API_TOKEN` | `dev-panel-token` | токен входа в панель; смените на боевом |

### Клиенты (фейк ⇄ боевой)

| Ключ | Значения | Назначение |
|---|---|---|
| `AVITO_CLIENT` | `fake` \| `playwright` | парсер и отправка: сид-данные или реальный браузер |
| `AI_CLIENT` | `fake` \| `deepseek` \| `openai` \| `chain` | ИИ; `chain` = DeepSeek с фолбэком на OpenAI |
| `TELEGRAM_CLIENT` | `fake` \| `aiogram` | доставка лидов |
| `AUTH_CLIENT` | `fake` \| `playwright` | вход в аккаунт: заглушка или настоящий браузер |
| `PROXY_PROVIDER` | `fake` \| `lteboost` | выдача прокси из кабинета провайдера |

### Внешние ключи

| Ключ | Назначение |
|---|---|
| `DEEPSEEK_API_KEY` | основной ИИ |
| `OPENAI_API_KEY` | запасной ИИ |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OPERATOR_CHAT_ID` | бот и чат оператора |
| `PROXY_API_KEY` | кабинет провайдера прокси |

Секреты берутся только из `.env` и никогда не логируются. Прокси-URL наружу отдаётся замаскированным (`http://***@host:port`).

### Поведение бота

Лимиты жёстко зажаты в доменной логике, панель не может выйти за них: суточный лимит ≤ 15 сообщений на аккаунт, задержка 5–15 минут, ротация 2–3 аккаунта, окно отправки 9–21. Значения по умолчанию — `DELAY_MIN_MINUTES`, `DELAY_MAX_MINUTES`, `DAILY_MESSAGE_LIMIT`; окно и выходные редактируются в панели и применяются без перезапуска.

## Перевод на боевой режим

### 1. Авито (парсер + отправка)

```env
AVITO_CLIENT=playwright
AVITO_HEADLESS=false
```

Авито детектит headless-браузер, поэтому Chromium в контейнере запускается headed под Xvfb — это уже настроено в образе. Каталог публичный, парсеру файл сессии не нужен: без него обход идёт анонимно.

### 2. Прокси

Авито режет датацентровые и «выжженные» резидентные адреса. Аккаунтам нужны липкие адреса, парсеру — отдельный транспорт, чтобы его нагрузка не пожгла IP аккаунтов.

Диагностика транспорта без ввода данных (открывает Авито, печатает, заблокирован ли адрес, сохраняет скриншот):

```bash
docker compose exec backend python -m tools.login_doctor "http://user:pass@host:port"
```

Пустой аргумент — проверка прямого соединения контейнера.

Провайдерский API включается флагом `PROXY_PROVIDER=lteboost` и ключом `PROXY_API_KEY`; после этого в панели работает кнопка «Выдать прокси» и карточка остатка трафика.

### 3. ИИ

```env
AI_CLIENT=chain
DEEPSEEK_API_KEY=...
OPENAI_API_KEY=...
```

`chain` шлёт запрос в DeepSeek и при недоступности автоматически переключается на OpenAI. Если модель вернула пустой текст, нераскрытый плейсхолдер или простыню сверх лимита, бот молча откатывается на исходный шаблон — сообщение уйдёт в любом случае.

### 4. Telegram

```env
TELEGRAM_CLIENT=aiogram
TELEGRAM_BOT_TOKEN=...
TELEGRAM_OPERATOR_CHAT_ID=...
```

## Заведение аккаунта Авито

Вход **полностью ручной** через noVNC — прямо в том браузере, которым потом работает бот. Панель не спрашивает и нигде не хранит логин и пароль от Авито.

Включите удалённый просмотр браузера:

```env
AUTH_CLIENT=playwright
VNC_ENABLED=true
VNC_PASSWORD=<пароль-для-noVNC>
VNC_PUBLIC_URL=http://localhost:6080/vnc.html
```

Порт noVNC публикуется только на `127.0.0.1` — за ним живой браузер с сессией аккаунта, наружу его открывать нельзя, ходите через SSH-туннель.

Дальше в панели: **Аккаунты → Добавить аккаунт**. Укажите название (метку), прокси и суточный лимит, нажмите «Открыть браузер», войдите в Авито в появившемся окне (телефон, пароль, код из СМС, капча — всё сами) и нажмите «Я вошёл». Бот проверит, что вы залогинены, и сохранит сессию.

> Логиньтесь через тот же прокси, на котором аккаунт будет работать: сессия, созданная с другого IP, разлогинится при первой же отправке.

## Панель

| Раздел | Что делает |
|---|---|
| **Дашборд** | статистика (отправлено / этапы / лиды), состояние сервисов, старт-пауза бота |
| **Категории** | CRUD категорий и регионов, фильтр «минимум объявлений у продавца» |
| **Парсер** | запуск обхода категории, таблица найденных продавцов |
| **Скрипты** | шаблоны 3 этапов × до 5 вариантов, плейсхолдеры `{name}` / `{product}` / `{category}` |
| **Расписание** | окно отправки, выходные, задержки, суточный лимит, размер ротации |
| **Аккаунты** | ротация, суточные лимиты, статусы, вход через noVNC, выдача прокси |

Все изменения применяются без перезапуска.

## Разработка

Бэкенд и фронтенд можно поднять локально без Docker.

### Бэкенд

```bash
cd backend
uv sync
uv run playwright install chromium
uv run alembic upgrade head
uv run python -m app.db.seed
uv run uvicorn app.main:app --reload
```

### Фронтенд

```bash
cd frontend
npm install
npm run dev
```

Панель ходит в бэкенд по `API_BASE_URL` (по умолчанию `http://127.0.0.1:8000`).

### Definition of Done

Перед коммитом:

```bash
# backend
cd backend
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest

# frontend
cd frontend
npm run check
npm run build
```

При изменении схемы БД миграция генерируется из моделей и должна чисто применяться на эфемерной базе:

```bash
cd backend
uv run alembic revision --autogenerate -m "описание"
uv run alembic upgrade head
```

## Структура

Монорепозиторий, слайсы вертикальные: домен → API-роут → страница панели.

```
backend/
  app/
    main.py            FastAPI, lifespan (APScheduler, DB)
    config.py          pydantic-settings, все ключи .env
    domain/            чистая логика без I/O (ротация, расписание, вариации, шаблоны)
    clients/           внешние клиенты за Protocol-интерфейсами (+ фейки)
      avito/  ai/  telegram/  proxy/
    parser/  outreach/  ai_pipeline/  leads/          слайсы-фичи
    accounts/  categories/  scripts_admin/  settings_admin/  dashboard/
    db/                модели, миграции, сид
  tools/               login_doctor — диагностика транспорта
  tests/               зеркалит app/
frontend/
  src/routes/(app)/    страницы панели (по слайсу на раздел)
  src/lib/ui/          примитивы shadcn-svelte
docker-compose.yml
```

Источник истины по архитектуре, схеме БД, контрактам и дорожной карте — [`tech.md`](tech.md).

## Тестирование

Тесты выводятся из критериев приёмки, а не зеркалят реализацию:

- **контрактные** — фейковые клиенты валидируют вход против Pydantic-схем;
- **идемпотентность** — обработчик этапа гоняется дважды с тем же payload, проверяется ровно один эффект;
- **путь ошибки** — фейк отдаёт таймаут / 500 / блокировку, проверяется корректная реакция;
- **property-based** (hypothesis) — на чистой доменной логике: подстановка плейсхолдеров, случайная задержка, суточный лимит, окно расписания.

```bash
cd backend && uv run pytest
```
